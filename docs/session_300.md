## The walk-harness lessons (L-141c1..c2)

- **L-141c1 the sibling-label checkbox locator**: the ui Checkbox
  renders `<div><button role=checkbox/><label htmlFor>Call</label></
  div>` — the label is a SIBLING of the button, so a
  `[role="checkbox"]` hasText filter matches NOTHING (the walk15-era
  locator silently no-op'd at both s125 and s141 — the interaction
  census recorded `int.callCheck` only after the fix). The working
  form: the label's preceding-sibling button (the XPath
  `//label[normalize-space(text())="Call"]/preceding-sibling::button
  [@role="checkbox"]` — verified on BOTH apps; the reference's own
  label carries `for="Call"`).
- **L-141c2 the badge-carrying tab accessible name**: at seeded state
  the Overdue tab's accessible name becomes "Overdue 3" (the count
  badge folds into the name) — a `getByRole("tab", { name:
  "Overdue", exact: true })` click times out; `exact: false` (the
  contains-match) is the seeded-phase form. The zero-phase plain
  labels keep exact:true working — the locator must be state-aware.
